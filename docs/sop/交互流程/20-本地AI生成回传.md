# §20 本地 AI 生成回传（T-040 追加，v3.1，2026-09-13 本人拍板口径起草，待文字层确认）

> 需求来源：2026-09-13 本人拍板三条——①生成范围照旧（S 全集、五类文本：译文/周榜/季榜/总星推荐语/AI 概要）；②周榜维持每周重生；③人工回填的行受保护、不被自动路径覆盖。本质＝把"应用直接调用远端 AI"换成"导出待生成任务 → 本人在本地对话式工具（WorkBuddy 等，无 API）生成 → 回填写入"，判定口径与既有每日 ensure 逐条一致。
> 组件分档：本变更纯接口、无新增界面元素（v1 不做页面面板），免示意图（2026-08-09 分档口径）。

### 20.1 定位与边界
- 本专章管"文本从哪来"的通道；文本的分类展示与渲染口径一概不变（§7 译文 / §8 推荐语 / §11 AI 概要继续有效）。
- 与自动路径的关系：AI 段关闭（`AI_ENABLED=0`）期间，导出接口即"待生成清单"的唯一来源；AI 段恢复后自动路径照旧只补缺失，且**人工行不参与自动重生**。
- 不做：不改生成节奏与范围（周榜维持每周重生）、不做页面面板（v1）、不恢复 `AI_ENABLED`。

### 20.2 主路径（两个接口，无界面）
1. **导出**：`GET /api/local-ai/tasks?limit=20&kind=all&format=text` → 一份自包含作业单：输出格式要求＋逐条任务的 system/user prompt 全文（README 已按 `AI_README_HEAD_CHARS`＝3000 字符截断）。
2. **本地生成**：把作业单整段贴给本地工具，要求它输出一个 JSON 对象 `{"items":[{"repo":…,"kind":…,"period_label":…,"text":…}]}`。
3. **回填**：`POST /api/local-ai/fill` 贴入该 JSON → 逐条校验后写入 → 返回 `written`/`skipped`/`errors` 明细。
4. 重复 1~3；**窗口日的收工判据＝本次导出没有任何 total/概要重生任务**（非窗口日＝`remaining` 归零）。`probe_skipped>0` 只表示"本轮还有候选没判定"（探测无服务端状态，重复导出不会清零、不代表剩余工作量），看到它继续"回填→再导出"即可逐批推进；周榜每进新周会再出现约 830 条新任务。

### 20.3 分支与异常
| 场景 | 走向 |
|---|---|
| 期次过期（跨周/跨季回填） | 该条计入 errors 并提示重新导出；同批其他条目照常处理 |
| 目标行已存在且未开 `overwrite` | 计入 skipped，库内文本不变 |
| 文本清洗后为空 / 超长 / 仓库不在池 | 计入 errors，不写库，不阻断同批 |
| 本地工具带引号或"推荐理由："前缀 | 服务端最小清洗后再写入（只去壳不改正文） |
| README 拉取失败 | 导出退化为元数据输入；回填的 total/summary 指纹写 NULL（该行若为 `source='ai'`，下次窗口日视为变更重生一次，自愈；**人工行不参与窗口日比对，指纹只是死数据**——见 §20.4） |
| 仓库简介变更（采集层） | 清该仓译文并删除其全部推荐语（**含人工行**，§8.4 既有口径）——输入已变即文本失效，下次导出会重新出现为缺失任务 |
| 批内重复键（同 repo+kind+期次） | 后到者按"已存在"计入 skipped |
| 请求体超 1MB / 条目超 200 | 整批拒绝并返回明确错误 |
| 未配置或关闭 AI（`AI_ENABLED=0`） | 两个接口完全可用，不受影响 |

### 20.4 服务端口径（钉死）
- **判定口径复用每日 ensure**：S = 三口径榜去重 ∪ 关注集；translate（未译且原文非空无 CJK）、week（当周缺行）、quarter（缺行或窗口日过期）、total/summary（缺行或窗口日 README sha 变更）。
- **覆盖语义**：默认只补缺失（与批量补缺同语义）；`overwrite=true` 才显式覆盖。写入行一律标记 `source='manual'`。
- **人工行保护**：自动路径（每日 ensure、手动批量补缺、窗口日的季/总/概要三档重生）不得覆盖 `source='manual'` 行；手动单仓"生成/重新生成"仍可覆盖（用户显式操作，写回 `source='ai'`）。
- **期次绑定**：week/quarter 的 `period_label` 必须与当前期次一致，total/summary 固定 `all`，translate 忽略。
- **指纹**：total/summary 行在回填时重取 README blob sha 作指纹；week/quarter 行 `readme_sha` 恒 NULL（与自动路径同口径）。
- **导出性能护栏**：窗口日 total/summary 已有行需拉 README 比对才能判定；**两段各持一份探测预算**（各为 `min(max(limit×8, 200), 500)`；共用会出现 total 段吃光预算、summary 段整轮零判定，`limit` 先被 total 段凑满也会让 summary 段整轮不跑）。未判定候选数由 `probe_skipped` 报出（两条原因都计入：预算耗尽、本批条数已满未跑到的段尾候选），`probe_truncated` 标记是否有未判定。单次实际约 200~400 次 GitHub 调用（≈单段预算，跨段缓存命中；理论上界 800）、1~3 分钟。推进方式：先回填本批（回填行是人工行、不再占探测预算），再导出下一批，逐批推进到后面的变更仓；**收工判据＝本次导出没有任何 total/概要重生任务**（`probe_skipped` 是告警值不是进度：无服务端状态、重复导出不清零、不代表剩余工作量）。
- **鉴权**：复用 Caddy Basic Auth 一层，无匿名入口；导出 `limit` 上限 50，回填单批条目上限 200、请求体上限 1MB。
