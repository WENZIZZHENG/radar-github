# §14 手动同步（T-029 追加，v2.4，2026-08-15 本人确认）

> 需求来源：2026-08-15 本人提出——部署改动或想立即看最新数据时，不等每日 05:00 调度。
> 组件分档：顶栏文字钮 / toast / 后台轮询均为既有冻结视觉体系组件复用（与 §7 批量补译、§8 批量推荐语同构），免示意图（2026-08-09 分档口径）。

### 14.1 元素与位置
- **手动同步按钮**：顶栏右端文字钮 **"立即同步"**（"补齐推荐语"旁，全页面共用顶栏）。

### 14.2 主路径逐步序列
1. 顶栏点"立即同步" → `POST /api/sync` 202 后台任务起 → 按钮置灰变"同步中…"（防连点）。
2. 前端每 2s 轮询 `/api/sync/status`；页面加载时若任务在跑，自动接管按钮态（与 §7.2 批量补译同口径）。
3. 完成 → toast"同步完成：快照 N 行、新发现 M 个、漂移 K 个"（带每日任务汇总统计），按钮恢复"立即同步"；toast 附提示"刷新页面查看最新榜单"（榜单已在任务内预计算，刷新即见新数据，不自动刷新页面——同步耗时长，自动刷新会打断正在阅读的人）。

### 14.3 分支与异常
| 场景 | 走向 |
|---|---|
| 进行中（含调度器每日 05:00 那轮正在跑）重复点击 | toast"同步进行中…"（服务端 running 态 409），进轮询接管 |
| 任务异常 | toast"同步失败，稍后再试"，按钮恢复；失败细节在服务器 jobs.log |
| DeepSeek key 未配置 | 不算失败：AI 段本就降级跳过，完成 toast 照常（与每日调度同口径） |

### 14.4 服务端口径（钉死）
- 同步＝**`daily_job` 全链路**（快照→发现→榜单预计算→AI ensure），与调度器走同一条代码路径，不另实现一套。
- 全局限额一个运行实例：调度触发与手动触发**共用同一把运行锁**，运行中任何来源再触发一律 409（调度器侧撞锁则跳过本轮，次日自然重试，与共识 §8 容错口径一致）。
- 幂等可重入（采集 INSERT OR REPLACE/IGNORE、预计算全量重算、AI 只补缺失），重复跑不产生脏数据。
- 运行状态只存进程内存（running/上次结果），不落库；服务重启状态归零，被中断的任务由次日调度自愈。
