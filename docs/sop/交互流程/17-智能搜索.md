# §17 智能搜索（T-034 追加，v2.7，2026-08-18 本人确认）

> 需求来源：2026-08-18 本人提出——做爬虫/桌面端/Java 项目时，想用自然语言搜出对应项目推荐；家底：池内 3024 仓（≥1000 星），主流语言够厚（Python 556/TS 543/Rust 264/Go 243/C++ 229），薄区（Java 131/C# 90/Kotlin 58）与未达千星的新生长尾由池外实时补搜覆盖。技术方案见 OpenSpec change `smart-search`（四件产物齐、strict 过）。
> 组件分档：输入框/按钮/徽标/结果行全复用既有冻结视觉体系组件（结果行＝榜单行组件），无新视觉元素，免示意图（2026-08-09 分档口径）。

### 17.1 元素与位置
- 新页面 P8 `/search`：顶部大输入框＋提交按钮＋结果列表；顶栏加"搜索"项（**顶栏上限由 5 调整为 6**，本次拍板）。
- 结果区顶部**意图透明行**："理解为：关键词1、关键词2 …／语言：…"（LLM 解析结果如实展示，可纠错可预期）。
- 结果行复用榜单行组件（紧凑行＋详情默认展开），行下多一句中文推荐理由（≤50 字，"为什么适合你的意图"视角）；**池外结果带"池外"徽标**（无增星/译文/概要，展示 GitHub 原始描述），行尾带关注星。
- 空结果：如实说明形态——"没有找到匹配「已理解的关键词/语言」的项目，换个说法试试？"（措辞以实现时定稿为准），不硬编任何条目。

### 17.2 主路径逐步序列
1. 输入自然语言（如"我要做爬虫，Python 的"）→ 提交 → 加载态提示（秒级）。
2. LLM 意图理解：产出**多个关键词 × 多个语言**（及主题词，不锁单个）→ 意图透明行展示。
3. 池内召回候选（约前 30）→ LLM 按匹配度精选 **10 条**＋各写一句推荐理由。
4. 池内不足 10 条 → 同组关键词实时 GitHub Search 补搜，补足 10 条为止；池内在前、池外在后。
5. 池外行点关注星 → 该仓动态入池（决策 9 链路），次日起有基线快照、增星、进翻译队列。

### 17.3 分支与异常
| 场景 | 走向 |
|---|---|
| DeepSeek key 未配置/鉴权失败 | 搜索页明确提示"搜索暂不可用（AI 未配置）"；榜单等主链路不受影响 |
| LLM 意图理解返回非法 JSON | 退化为以原输入作单一关键词的池内检索，不报错页 |
| LLM 精选失败（非法返回/超范围引用） | 按粗排顺序直出池内候选（至多 10 条，无推荐理由），记 WARNING |
| GitHub Search 失败/限速/token 缺失 | 跳过补搜：只出池内结果，池外区标注"补搜失败"或不渲染 |
| 池内＋池外全空 | 如实空结果说明（§17.1），无任何编造条目 |

### 17.4 服务端口径（钉死）
- 三段式链路：LLM 只做意图理解与精选润色，**检索在本地 SQL / GitHub API 做**——候选集永远来自真实数据，LLM 无幻觉出不存在项目的机会；精选时 LLM 只许从候选清单中按编号选择。
- 池内召回：alive 仓按关键词组匹配（全名/英文描述/topics 任一命中任一关键词计一次），语言过滤取交集；粗排＝命中数降序 → 最新星数降序，取约前 30。
- 精选：至多 10 条按匹配度排序；不足 10 条有几个列几个，不凑数。
- 池外补搜：仅池内 <10 条时触发；结果模型带 external 标记；单次搜索至多 1~2 次 Search 调用（限速 30 次/分，单人够用）。
- 成本：每次搜索 1~3 次 DeepSeek 调用；不建搜索缓存（重复搜代价可接受，痛点真出现再议）。
- 关注闭环：复用 `ingest_followed_repo`（source='follow'＋基线快照）；已在池/已关注的池外行不显示关注入口（full_name 查库判定）。
