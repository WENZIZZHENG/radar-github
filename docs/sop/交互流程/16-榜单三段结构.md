### 16.1 位置与元素
- P1/P2/P3/P4 榜单四页的**每个分类榜块内**，三段结构自上而下：**新崛起区（既有，区头不变）→ 新项目区 → 主榜**；三区各有对仗 h4 区头——"新崛起 · 入池未满一个统计窗口"（既有）／"新项目 · 创建未满 1 年"／"主榜 · 按本期增星排序"（P4 总星榜为"主榜 · 按总星排序"）；区头计数徽标同榜头形态（不足标实际值）。
- P4 总星榜有新项目区（按总星排序）而无新崛起区（§9.1 既有口径不变）；P5/P6 不设分区（页语义不变，同 §9.1 口径）。
- 新项目区行形态与主榜行完全一致（紧凑行＋详情默认展开＋翻译/推荐语/标签/★）；**增量列为窗口增量**（与主榜同口径，区别于新崛起区的"入池 N 天"标注）。
- **创建年份标注**：榜单行全名旁加创建年份小灰字（如 "· 2024"）；共用行模板的全页面（P1/P2/P3/P4/P5/P6）同步生效；创建时间未知（未回填）的行不显示标注，不留空位。

### 16.2 主路径与分支
- 空区不渲染：新项目区无成员时不出现区头（榜块本体照常；**主榜区头恒渲染**，不受新区空满影响）。
- 三区流转（同榜内同仓只出现一次）：新仓入池不足最小窗口 → 新崛起区；满窗口毕业且创建未满 1 年 → 新项目区；凭增量进入主榜 Top 50 → 只在主榜；创建满 1 年 → 只凭主榜资格出现。无用户感知事件。
- 上线首日新项目区为空或零星（创建时间待次日日常采集顺手回填），次日满血——顺手回填方案的既定代价，已拍板接受。

### 16.3 服务端口径（钉死）
- 新项目区准入：`as_of − github_created_at < 365 天`；周/季榜另需出席（新崛起区收缺席仓，两区天然互斥）；总榜无出席概念；`github_created_at IS NULL` 一律不进；**已进入本榜主榜 Top 50 的仓不重复进新项目区**（full_name 去重）。
- 排序与行数：周/季按窗口增量降序、总榜按总星降序（次序键同主榜 `_top`）；每区 Top 20，不足按实际、不补位。
- 数据来源：repos 新增 `github_created_at` 列（GitHub 创建时间；既有 `created_at`＝入池时间不动）；每日 GraphQL 批量采集落库时顺手写入（`NODES_QUERY` 本已返回 `createdAt`），新仓入池（Search 发现/关注入池）同样顺手存——零额外 API 开销。
- AI 覆盖范围 S 集扩展：三口径榜集由"主榜 Top50 ∪ 新崛起区 Top10"扩为"主榜 Top50 ∪ 新崛起区 Top10 ∪ **新项目区 Top20**"（其余口径不变）——新项目区行的翻译/推荐语/概要与主榜行同待遇。
