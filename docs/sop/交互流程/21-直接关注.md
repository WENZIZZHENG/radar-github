# §21 直接关注（粘贴仓库地址添加关注，v1，2026-10-18 本人确认）

> 需求来源：2026-10-18 本人提出"已明确知道 GitHub 地址的项目要能直接加入关注"。关注入口在项目行右侧 ☆，前提是该仓库已出现在榜单或搜索结果里；只知道地址、又不在当期榜单命中的仓库没有可达的关注入口。本专章钉死：入口位置、接受的地址形态、服务端归一与三态写入口径、结果横幅与失败文案、既有边界（不改名归并／不批量／添加时不打标签）。技术方案见 OpenSpec change `direct-follow`。
> 组件分档：输入框／按钮／横幅／行组件全复用既有冻结视觉体系组件，无新视觉元素，免示意图（2026-08-09 分档口径）。

### 21.1 入口与位置
- 位置：P6「我的关注」页（`/follows`）**元信息行下、标签筛选行上**的一行地址输入框＋「关注」按钮。
- 输入框下有一行口径提示："支持 github.com 链接、git@github.com:owner/repo.git 与 owner/repo；已关注的仓库不会重复写入。"
- 空关注页（关注数为 0）**同样显示**该输入入口，与空态说明并存。
- 原生表单提交：无 JavaScript 时照常可用；提交即关注，与项目行右侧 ☆ 同义——不经过 AI、不调用搜索链路。
- 页内唯一写入口对应服务端唯一页面路由 `POST /follows/add`；不新增 JSON 接口、不在其它页面复制添加入口。
- 搜索页只加一行引导（§21.7），不构成第二处添加入口。

### 21.2 输入形态

| 形态 | 示例 | 处置 |
|---|---|---|
| https/http 链接 | `https://github.com/psf/requests` | 接受 |
| 链接带子路径／查询串／片段 | `https://github.com/psf/requests/tree/main?tab=readme#intro` | 接受（取路径前两段） |
| www 域名／末尾斜杠／`.git` 后缀 | `https://www.github.com/psf/requests.git/` | 接受 |
| 省略协议 | `github.com/psf/requests` | 接受 |
| SSH 形态 | `git@github.com:psf/requests.git`、`ssh://git@github.com/psf/requests.git` | 接受 |
| 裸 owner/repo | `psf/requests` | 接受（见下） |
| 非 github.com 域名（含企业版） | `https://gitlab.com/psf/requests`、`https://github.company.internal/psf/requests`、`gitlab.com/psf` | 拒绝（400） |
| 只有 owner 没有 repo | `psf` | 拒绝（400） |
| GitHub 保留页前缀 | `https://github.com/settings/profile`、`https://github.com/orgs/psf`、`https://github.com/collections/awesome` | 拒绝（400） |
| 非法字符或超长 | 含换行／空白分隔多个片段、超 owner 39＋repo 100 | 拒绝（400） |
| 批量多地址 | 换行拼接两个地址 | 拒绝（400，不做批量） |

- **裸 `owner/repo` 只在关注页接受**：搜索页不接受裸名，避免 `react`、`vue` 这类词被误判成仓库。
- **裸名的近似形态**：`psf/requests/` 与 `psf/requests.git` 按同一归一口径处理（等同 `psf/requests`），不原样拿去请求 GitHub；多于两段的裸形态（如 `psf/requests/extra`）仍按 400 拒绝。
- **大小写不敏感**：GitHub 仓库名大小写不同属同一仓库；输入大小写与库内记录不同也命中同一条记录，结果与横幅使用库内（已入池）或 GitHub 返回（新入池／复活）的**规范名**。

### 21.3 主路径逐步序列
1. 在「我的关注」页顶部输入框粘贴地址（如 `https://github.com/psf/requests`）→ 点「关注」。
2. 服务端把输入归一为 `owner/repo`；归一失败即按 §21.4 的 400 停在原页并保留输入。
3. 按库内状态走既有三态关注写路径：已入池且正常只补 follows 行；已标记失效（dead）复活并补一张基线快照；未入池抓一次单仓元数据入池（`source='follow'`）并补基线快照；已在关注列表则幂等短路（不重复写入、不调用 GitHub）。
4. 成功 → 303 跳回 `/follows?added=<规范名>&result=<joined|revived|alive|already>`。
5. 关注页渲染结果横幅（附"在下方「{语言组}」组查看"锚点），该仓库行出现在对应语言分组；顶栏关注计数与实际关注数一致（新关注 +1，已关注不变）；无增量数据的新关注行沿用"—— 下周起有数据"标注。

### 21.4 结果横幅与失败文案

成功（结果横幅；`{full_name}` 为规范名）：

| result | 触发 | 文案 |
|---|---|---|
| `joined` | 此前不在池内 | `已关注 {full_name}：此前不在池内，已即时抓取基线快照并入池，下周起显示当周增量。` |
| `revived` | 库内已标记失效 | `已关注 {full_name}：此前已标记失效，已复活并补一张基线快照，次日起恢复每日采集。` |
| `alive` | 已在跟踪池内、未关注 | `已关注 {full_name}：该仓库已在跟踪池内，无需额外抓取。` |
| `already` | 已在关注列表 | `{full_name} 已经在关注中，未做重复写入。` |

- 四类成功横幅一律附**"在下方「{语言组}」组查看"**锚点链接（形如 `#f-python`；无语言归「其它语言」组，锚点 `#f-other`）。

失败（不跳转，同页渲染原因并保留输入框原值）：

| HTTP | 触发 | 文案 |
|---|---|---|
| 400 | 输入无法归一为 owner/repo | `无法识别仓库地址：{输入}。支持 https://github.com/owner/repo、git@github.com:owner/repo.git 或 owner/repo。` |
| 404 | GitHub 上不存在（不存在／已删除／转私有） | `GitHub 上找不到仓库 {full_name}（不存在/已删除/转私有）` |
| 409 | node_id 撞库（仓库已改名或同名重建） | 沿用既有文案（仓库可能已改名/同名重建，暂未自动归并） |
| 500 | GitHub token 未配置／无效 | 沿用既有 GitHub token 配置错误文案 |
| 502 | GitHub 请求失败 | `GitHub 请求失败：{原因}` |

- 失败页**原样回填输入框**（浏览器输入框上限 300 字内的输入不截断）；请求体超过 8KB 的异常直连提交按固定短文案"输入过长"拒绝、不回显原文（防御分支，正常表单不会触发）。
- 手动改地址栏的 `added`／`result` 参数**只影响展示**（可能看到与当前状态矛盾的成功类说明），不改库内任何状态；参数经白名单与关注集校验，不渲染任意文本。

### 21.5 服务端口径（钉死）
- **解析单一入口**：服务端一个解析模块统一归一，前端零解析；接受与拒绝形态按 §21.2。
- **大小写不敏感**：查库按大小写不敏感命中，结果与横幅使用库内（已入池）或 GitHub 返回（新入池／复活）的规范名。
- **写路径唯一**：只经既有三态关注写路径（决策 9 动态入池：已入池 alive 只补 follows 行／dead 复活＋基线快照／未入池抓单仓元数据入池＋基线快照），不新增第二条写路径。
- **GitHub 调用次数**：已入池 0 次；未入池与复活各 1 次（单仓元数据）；重复关注 0 次（幂等短路）。
- **反馈形态**：成功走 PRG（303 跳回关注页，GET 渲染横幅）；失败同页渲染，HTTP 状态与错误类别一致（400／404／409／500／502）。
- **提交防护**：表单只接受同源提交（请求带 `Origin` 且其主机名与站点的 `Host`/`X-Forwarded-Host` 都不同源时 403；403 是防御分支，返回 JSON 提示、不渲染关注页），请求体上限 8KB（带 `Content-Length` 时在读请求体前拒绝）；两者都是防御分支，正常页面提交不会触发。
- **不自动归并**：库内 `full_name` 不被改写（§21.6）；取消关注只删 follows 行、仓库与快照保留（决策 9 跟踪保留）。

### 21.6 边界
| 情形 | 走向 |
|---|---|
| 仓库已改名（旧链接） | 单仓元数据请求跟随 GitHub 的 301 跳转；未入池 → 按新名入池，横幅用新名 |
| 旧链接指向已跟踪仓库 | 新名 node_id 已存在于库内 → 409 如实报告，库内 `full_name` 不改写、不自动归并（本人知情处置） |
| 同名重建（node_id 已变化） | 409，同上 fail-loud 口径 |
| 一次提交多个地址 | 不做批量：按单地址解析失败处理（400），不关注其中任何一个 |
| 非 GitHub 域名（含企业版） | 不支持（400） |
| 添加时打标签 | 不支持：添加只管关注；打标仍在项目行详情面板（§3.3） |
| 搜索框识别地址直出 | 不支持（§21.7） |

### 21.7 搜索页引导
- P8 搜索页在**搜索框下**加一行静态提示："已知仓库地址？到「我的关注」粘贴地址即可直接关注（不经过 AI 搜索）。"（"「我的关注」"链接 `/follows`）。
- 该提示**不改**搜索表单的输入契约（自然语言描述）、**不改**检索链路（意图理解 → 池内召回 → AI 精选 → 池外补搜）、**不改**流式加载态的事件协议。
- 把地址粘进搜索框，仍按既有自然语言链路处理（不识别、不直出关注结果）。
- AI 不可用时搜索页的既有降级形态（表单禁用＋提示）不变，该行引导照常显示。
