## 1. 主栈一览
- 前端：Jinja2 服务端渲染 + 少量原生 JS（无前端框架）
- 后端：Python 3.12+ / FastAPI + httpx（async）+ APScheduler（进程内调度）
- 数据库：SQLite（WAL 模式，单文件）
- AI：DeepSeek API（deepseek-chat）
- 部署：云服务器 systemd 托管 uvicorn；Caddy 反代（已有域名，自动 HTTPS + basic auth）

## 2. 系统架构与链路时序（S 档裁剪：文字链路清单，不出架构图）

**部署形态**：浏览器 → Caddy（自动 HTTPS＋Basic Auth，唯一公网入口）→ `127.0.0.1:8000` uvicorn（systemd 托管，radar 用户）→ `/opt/radar/data/radar.db`（SQLite WAL）；radar 用户 crontab 每日 03:17 跑 `scripts/backup.sh`（本地留 14 份；异机传输待 `BACKUP_REMOTE` 配置）。

**四条主链路（时序要点）**：
1. **每日采集**（北京 05:00 / UTC 21:00，进程内 APScheduler）：GraphQL `nodes(ids:)` 按 100/批拉 alive 仓的星数/简介/语言/topics/创建时间（批内删除仓剔除后重试）→ 写 `star_snapshots` 并按漂移更新 `repos` → 发现池 Search 补新面孔（`source='discover'`＋基线快照）→ 三口径榜单预计算落 `board_cache` → AI 段（`AI_ENABLED=1` 时）补译/推荐语/概要。任一段失败只影响本段，不阻塞出榜。
2. **页面读取（SSR）**：期次/榜单参数解析 → `board_cache` 命中直读；缺失或过期降级 `compute_boards` 实时算（同一实现，不产生第二套口径）→ Jinja2 渲染行组件（`_row.html` 为行形态单一事实源）。
3. **关注写路径（单一）**：行内 ☆ 或 P6 地址添加 → `POST /api/follows` 或 `POST /follows/add` → `follow_repo` 三态（alive 只补 follows／dead 复活＋基线／未入池 REST 单仓入池＋基线）→ 次日起进入每日采集；取消关注只删 follows 行（跟踪保留）。
4. **智能搜索（P8）**：自然语言 → LLM 意图理解 → 池内 SQL 召回＋LLM 精选 → 池内不足时 GitHub Search 补足；流式与同步两条路径跑同一 `run_search`、渲染同一结果 partial。

**容量与成本量级**（v3.0 模板要求的量级预算，非精确值）：读路径 QPS 单人使用 < 0.1；**当前**池约 1.07 万仓、快照 43.5 万行、库 46MB（2026-10-18 实测），**设计上限**为 6.4 万仓 ≈ 每日 6.4 万行（决策 1/2 的池规划），库体积随快照线性增长；运行在既有 40G 云盘（余 27G），无新增带宽与服务成本；AI 成本走中转站额度，无按量计费承诺（2026-08-20 降频后调用量降至原 10~15%）。

## 3. 数据模型概要
- `repos`：仓库主表（id, full_name, node_id, description_en/zh, language, topics JSON, dead 标记, 入池来源/时间）；中文翻译懒写入本表（node_id＝GraphQL Relay 全局 ID，每日 `nodes(ids:)` 批量采集必需；初版字段清单遗漏，2026-08-09 勘误补入）
- `star_snapshots`：星数快照（repo_id, captured_at, stars），主键 (repo_id, captured_at)，每日每仓库一行
- `follows`：关注（repo_id, created_at）
- `tags`：自定义标签（repo_id, tag）
- `recommendations`：推荐理由（repo_id, dimension[week/quarter/total], period_label, text, readme_sha NULL）；周/季维度按周期重生成、总星维度懒生成＋README 变更（sha 指纹）当日重生（2026-08-11 决策 6 v2，dimension/readme_sha 列由 T-017 幂等迁移补入）
- 榜单口径由 `compute_boards` **单一实现**：每日跑批预计算落 `board_cache`（T-027 物化），页面命中直读、缺失或过期降级实时算（两快照差值排序），两条路径同源不产生第二套口径——详见 §2 链路 2；建表 `app/schema.sql`、计算 `app/report.py`、跑批 `app/jobs.py`
