# 需求清单（阶段①冻结物）

> 确认状态：【未确认】　确认日期：【　】　版本：v【　】　基线：dev-sop v1.4
> 详细决策背景见 `docs/sop/共识文档.md`（已确认 v2）。

## 1. 项目一句话
为本人（单人）做一台全自动 GitHub 雷达：每日采集星数、每周产出分语言/分主题的增量榜单，扩展技术知识面、支撑项目选型参考。

## 2. 目标用户
- 是谁：本人，仅限单人使用。
- 在什么场景下使用：每周日打开网页看本周榜单；平时偶尔翻看、给感兴趣的项目点关注/打标签；季度末看趋势回顾。

## 3. 核心场景（按重要性排序）
| # | 场景（谁在什么情况下，想做什么，得到什么结果） |
|---|---|
| S1 | 每周日我打开周报页，浏览 17 个分类榜，快速发现本周升温的项目，扩展知识面 |
| S2 | 看到感兴趣的项目，我点关注或打自定义标签，之后每周在"我的关注"区直接看到它的当周增量，并能按标签回溯 |
| S3 | 季度末我打开季度回顾，看 90 天累计增量榜，识别持续升温的技术趋势，为选型提供参考 |
| S4 | 首次部署后（还没有 7 天数据时），我打开首页能看到初始全明星榜，不面对空页面 |

## 4. 本版本做（In Scope）
- 分层跟踪池采集：核心池（≥1000 星）每日 GraphQL 批量快照 + 发现池每日增量搜索
- 周度报告（7 天增量，17 分类各 Top 30，可回看历史周次）
- 季度回顾（90 天增量）与总星榜（备查 + 首期填充）
- 懒翻译（DeepSeek，首次进入展示面时翻译）+ 每周推荐理由（按项目生成、跨榜复用、每周重新生成）
- 关注（关注即动态入池）与自定义标签筛选
- 部署：Caddy 自动 HTTPS + Basic Auth；每日备份 + 每周异机一份

## 5. 不做清单
- 不做全站 ≥100 星全量跟踪（实测 47.2 万个，每日需 47 万次 API 请求，超配额 4 倍，物理不可行）
- 不做突发黑马追踪、不做任何主动推送（邮件/Telegram/通知一律没有）
- 不做用户系统/多人使用/注册登录页
- 不做无 topics 项目的 AI 二次归类（沉入"其他"榜即接受）
- 不抓 README、不回填星数历史（API 拿不到，也不买第三方数据）
- 不做原生 App/小程序（仅响应式 Web 页面）

## 6. 成功标准（可衡量，版本验收时逐条对照）
- 部署后第 7 天自动产出第一份周报，17 个榜齐全（不足 30 按实际数量），无需人工干预
- 连续运行 14 天无人工介入，期间允许静默容错但榜单日期连续可解释
- 关注/打标后刷新页面仍在（能延续），关注的低星项目第二周起能显示当周增量
- DeepSeek 累计费用 < ¥10/月
- 本人连续 2 周真实打开并看完周报（版本级验收以本人走查为准）
