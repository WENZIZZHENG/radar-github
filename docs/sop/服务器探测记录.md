## 1. OS 与 systemd 版本

- 命令：`cat /etc/os-release`；`systemctl --version`
- 看什么：发行版与版本号（预期 Debian/Ubuntu 系）、systemd 版本号。
- 为什么：`deploy/radar.service` 按现代 systemd 编写（`EnvironmentFile=-` 可选前缀等）；Caddy 官方 apt 源安装步骤也按 Debian/Ubuntu 给出。若是 CentOS/openSUSE 等其他系，安装命令与 nologin 路径（`/usr/sbin/nologin`）都要跟着换。
- 执行结果：**CentOS Stream 9**（非 Debian 系——包管理走 dnf，sqlite3 用 `dnf install -y sqlite`；nologin 路径 /usr/sbin/nologin 在 CentOS 9 有效（/sbin→usr/sbin 符号链接）；Caddy 已装（第 10 项），无需 apt 源步骤）。systemd 版本未单测，radar.service 语法（EnvironmentFile 可选前缀、RestartSec）属现代 systemd 基础能力，CentOS 9 的 systemd 252 完全覆盖。

## 2. CPU / 内存 / 磁盘

- 命令：`nproc && free -h && df -h /`
- 看什么：与已知规格（4 核 8G）核对；根分区剩余空间。
- 为什么：venv + 代码 + SQLite 数据 + 14 份滚动备份长期占盘，建议剩余 ≥10G；8G 内存对单 uvicorn + Caddy 很宽裕，此项主要是核对、防开错机器。
- 执行结果：**4 核 / 7.5G（可用 4.8G）/ 根分区 40G 余 27G（28%）**——与已知规格一致，余量充足。

## 3. 端口监听现状

- 命令：`sudo ss -tlnp`
- 看什么：8000 是否已被占用（雷达要用）；80/443 是否已被占用（Caddy 要用）、被谁占用。
- 为什么：8000 被占就要改端口，且 `deploy/radar.service` 的 `--port` 与 `deploy/Caddyfile` 的 `reverse_proxy` 目标必须同步改；80/443 被旧 Web 服务占着，Caddy 起不来也签不了证书，先处理冲突（见第 4 项）。
- 执行结果：**8000 空闲可用**；80/443 由 caddy（pid 1425731）监听——既有 Caddy 正常占位，属预期（雷达站点块追加进既有 Caddyfile，共用 80/443，不冲突）。

## 4. 已有 Web 服务

- 命令：`command -v nginx caddy apache2`；`systemctl list-unit-files | grep -Ei 'nginx|apache|caddy'`
- 看什么：nginx/caddy/apache 是否已安装、是否 active。
- 为什么：决定路线——已装 Caddy 就直接替换 `/etc/caddy/Caddyfile` 复用；已装 nginx/apache 且不再需要，先停并 disable（不急着卸，留回退余地）再装 Caddy；裸机则直接装 Caddy（第 10 项）。
- 执行结果：**仅 Caddy（/usr/bin/caddy），caddy.service active＋enabled**；无 nginx/apache。**路线修正（重要）：不替换既有 /etc/caddy/Caddyfile**——该文件手工维护（640 root:caddy），已承载 example.com（h5 SPA）、www 跳转、admin.example.com（admin SPA＋Basic Auth＋反代 :18080）三个站点块且证书已自动签发；雷达只**追加** radar.example.com 独立站点块，既有三个块一个字节不动。

## 5. 防火墙与安全组

- 命令：`sudo ufw status 2>/dev/null || sudo iptables -L INPUT -n`
- 看什么：80/443 是否放行。**云安全组在机器上探不到，必须去云厂商控制台核对入站 80/443 规则**，两层都要放。
- 为什么：Caddy 自动签发证书必须 80 可达（ACME HTTP-01 挑战），HTTPS 访问必须 443 可达，缺一不可；只放 443 不放 80 是签证书失败的经典原因。
- 执行结果：机器防火墙 **firewalld inactive**（机器层全放）；云安全组 80/443 **本人确认已放行**（2026-08-13）。

## 6. 域名 DNS 指向

- 命令：`dig +short <你的域名>`（无 dig 用 `nslookup <你的域名>`）；`curl -4 ifconfig.me`（本机公网 IP）
- 看什么：域名解析结果是否等于本机公网 IP。
- 为什么：DNS 未指向前 Caddy 签不到证书，先别启动 Caddy 站点；指向后签发/续期全自动。若域名还指着旧机器，规划好切换窗口再改 A 记录。
- 执行结果：**radar.example.com → <SERVER_IP>，与本机公网 IP（curl -4 ifconfig.me 实测）一致** ✓。

## 7. Python ≥3.12

- 命令：`python3 --version`；`command -v python3.12`
- 看什么：系统 Python 是否 ≥3.12。
- 为什么：项目要求 Python ≥3.12，而 Debian 12 默认只有 3.11。版本不够**不要**急着折腾系统级安装——`uv python install 3.12` 让 uv 自管一份即可，最省事且不污染系统。
- 执行结果：系统 Python **3.9.21**，不满足（无 python3.12）——按预案走 `uv python install 3.12`（uv 自管，不污染系统）。

## 8. uv

- 命令：`command -v uv`；`uv --version`
- 看什么：是否已装、装在哪个用户目录下。
- 为什么：依赖安装走 uv（`uv venv .venv && uv pip install -r pyproject.toml`）。官方安装脚本 `curl -LsSf https://astral.sh/uv/install.sh | sh` 装到**当前用户** `~/.local/bin`——radar.service 以 radar 用户运行，建议以 radar 身份装，或装好后放公共 PATH，避免 service 里找不到。
- 执行结果：**未安装**——按 radar.service 头注释步骤 3，以 radar 身份＋其 HOME 用 `sudo -u radar -H bash -c` 形态安装（nologin 用户不能 -i 登录）。

## 9. sqlite3 CLI

- 看什么：是否可用。
- 为什么：`scripts/backup.sh` 的热备依赖 sqlite3 CLI 的 `.backup` 命令。未装则 `sudo apt install -y sqlite3`。
- 执行结果：**未安装**——CentOS 9 包名 sqlite，部署时 `dnf install -y sqlite`。

## 10. Caddy

- 命令：`command -v caddy`；`caddy version`
- 看什么：是否已装及版本号。起草的 Caddyfile 以 v2.8 语法为准，`basic_auth` 指令名自 v2.8.0 起才有（此前名为 `basicauth`）——若已装的是 v2.8.0 以下旧版，先升级。
- 为什么：未装按官方 apt 源安装（Debian/Ubuntu）……（安装步骤略，本机不需要）。
- 执行结果：**已装 v2.11.4**（≥2.8，basic_auth 语法兼容）✓，service enabled＋active。配置结构：单文件 /etc/caddy/Caddyfile（无 conf.d 拆分），手工维护不入 git。

## 11. 时区与时间同步

- 命令：`timedatectl`
- 看什么：当前时区、NTP 是否同步（`System clock synchronized: yes`）。
- 为什么：每日采集、cron 03:17 备份、备份文件名时间戳全部按系统时钟走；时区不符预期就 `sudo timedatectl set-timezone Asia/Shanghai`（按本人所在地）。NTP 不同步会导致证书校验与榜单日期计算出问题。
- 执行结果：**Asia/Shanghai（CST, +0800）**，与本人所在地一致 ✓；系统时钟走 NTP（CentOS 9 默认 chrony 同步，未单测——采集口径全部 UTC 硬约定，榜单日期按 UTC 算，时区只影响 cron 触发点，03:17 备份按本地时区预期一致）。
