## 3. 端口监听现状

- 命令：`sudo ss -tlnp`

## 4. 已有 Web 服务

## 5. 防火墙与安全组

- 命令：`sudo ufw status 2>/dev/null || sudo iptables -L INPUT -n`
- 看什么：80/443 是否放行。**云安全组在机器上探不到，必须去云厂商控制台核对入站 80/443 规则**，两层都要放。
- 为什么：Caddy 自动签发证书必须 80 可达（ACME HTTP-01 挑战），HTTPS 访问必须 443 可达，缺一不可；只放 443 不放 80 是签证书失败的经典原因。
- 执行结果（待填，含安全组控制台确认）：

## 6. 域名 DNS 指向

- 命令：`dig +short <你的域名>`（无 dig 用 `nslookup <你的域名>`）；`curl -4 ifconfig.me`（本机公网 IP）
- 看什么：域名解析结果是否等于本机公网 IP。
- 为什么：DNS 未指向前 Caddy 签不到证书，先别启动 Caddy 站点；指向后签发/续期全自动。若域名还指着旧机器，规划好切换窗口再改 A 记录。

## 10. Caddy

- 命令：`command -v caddy`；`caddy version`
- 看什么：是否已装及版本号。起草的 Caddyfile 以 v2.8 语法为准，`basic_auth` 指令名自 v2.8.0 起才有（此前名为 `basicauth`）——若已装的是 v2.8.0 以下旧版，先升级。
- 为什么：未装按官方 apt 源安装（Debian/Ubuntu）：
  ```bash
  sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
  curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
  curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
  sudo apt update && sudo apt install -y caddy
  ```
  装完官方包会默认拉起 caddy 服务并占用 80/443——属预期，下一步就是替换 `/etc/caddy/Caddyfile` 并注入环境变量（步骤见 `deploy/Caddyfile` 头注释）。
