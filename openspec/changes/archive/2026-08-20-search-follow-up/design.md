# 设计：智能搜索追问与扩量（search-follow-up）

> 决策均已 2026-08-19 grilling 拍板（Q3~Q6）；本文件只固化技术取舍。

## 决策 1：追问上下文无状态，前端回传

- 追问时前端随表单回传两个隐藏字段：`prev_intent`（上一轮 Intent 的 JSON：raw_query/keywords/languages/topics）与 `prev_results`（上一轮结果摘要 JSON：每行 full_name＋理由＋池内外标记＋语言＋星数＋创建年份，仅供空结果时原样重渲染）。
- 服务端不建会话表、不落库；`prev_intent` 缺失/JSON 非法/字段形态非法 → 丢弃，按首搜处理（不报错）。
- 单人自用工具，回传内容可被手改但无安全问题：prev_intent 只影响检索条件（关键词经既有归一/运算符预算截断），prev_results 只用于展示重渲染（模板转义照常）。
- 备选（否决）：服务端会话表——为单人工具引入存储与生命周期管理，重。

## 决策 2：意图合并在 LLM 意图理解段完成

- `understand_intent` 扩展可选参数 `prev_intent`（或等价新方法）：prompt 携带旧意图 JSON＋本轮新输入，要求 LLM 产出**合并后的新意图**（同一 JSON 契约）——"只要异步的"→ 关键词追加 async；"换成 Go"→ 语言替换为 Go。
- 合并调用返回非法 JSON → 退化为**本轮新输入**单关键词（不沿用旧意图，spec 钉死）；调用失败/Auth 错误沿用既有降级姿态。
- 合并后意图经 `_build_intent` 同一归一/校验路径（关键词去重、语言对齐 LANGUAGES 键集、非法值丢弃）。
- 备选（否决）：服务端规则式合并（新输入关键词直接追加旧意图）——"换成 Go"这类替换语义规则写不出，必须 LLM 理解。

## 决策 3：追问搜空时上一轮结果保留

- 触发条件：本次为追问（prev_intent 有效）且新意图检索池内＋池外全空。
- 服务端用 `prev_results` 摘要原样重渲染上一轮结果区（标注"上一轮结果"＋新旧意图对比："旧意图 → 新意图"），顶部空结果说明沿用既有如实口径；不为此重跑旧意图检索（省一次 LLM 调用，且重跑理由文案会与用户所见不一致）。
- `prev_results` 缺失/非法 → 只显示空结果说明（退化为首搜空态）。

## 决策 4：数量 10→20 的连锁口径

- `RESULT_LIMIT` 10→20（精选至多 20、池外补足 20）；`POOL_TOP_N` 30→50（给精选留筛选余地，30 选 20 近乎全选、理由注水）。
- `_github_query` 运算符预算不变（关键词截前 4、语言截前 2，GitHub 单查询 ≤5 个布尔运算符）；补搜仍至多 2 次 Search 调用（per_page=100 两页足够补 20）。
- 精选 prompt 上限文案同步 20；理由仍 ≤50 字/条。
- 成本：单次搜索 DeepSeek token 约为原口径 2 倍（候选 50 payload＋20 条理由），本人拍板接受；不建缓存口径不变。

## 决策 5：页面形态

- 单输入框复用：首搜/追问同一输入框（结果页顶部原框），提交即带隐藏字段；意图透明行始终显示当前生效的合并意图；无轮次历史、无单独追问框。结果页同一框提交即视为追问（框无法区分"追问"与"重输"，单框设计固有边界）；全新搜索经导航入口（GET /search）进入，不带上轮字段，自然回到首搜路径。

## 决策 6：结构化筛选条件白名单（filters）

- 动因：追问/首搜中的非文本条件（"创建时间 1 年内"）在三字段契约（关键词/语言/主题词）里无处安放，硬塞关键词会被文本匹配吞掉（2026-08-19 本人实测反馈）。
- 契约：意图 JSON 增可选 `filters` 对象与 `unsupported` 数组。filters 第一版白名单两项——`created_within_days`（int，创建至今天数上限）、`min_stars`（int，最新星数下限）；LLM 只许产出白名单内字段，白名单外条件 MUST 进 `unsupported`（仅展示、不影响检索），MUST NOT 塞进关键词。
- 数据可得性决定白名单：池内 SQL 只能筛我们真存的字段（github_created_at、最新快照星数、语言、文本）；"最近活跃"（pushed_at）未采集故不支持——进 unsupported 回显。扩白名单＝prompt 示例＋服务端校验＋SQL 过滤＋补搜限定词四处对齐的小改动。
- 池内映射：`created_within_days` → `github_created_at` 非 NULL 且距今 <N 天（NULL 不进，与新项目区同口径）；`min_stars` → 最新快照星数 ≥N。
- 池外映射：`created_within_days` → `created:>YYYY-MM-DD` 限定词；`min_stars` → `stars:>=N`；限定词不占 GitHub 单查询 5 个布尔运算符预算（关键词截前 4、语言截前 2 的口径不变）。
- 追问合并：filters 随意图一起合并——新输入的条件覆盖同名字段（"1 年内"→"半年内"），未提及的保留。
- 意图透明行扩展：filters 生效段（"创建：近 1 年内"形态）＋unsupported 段（"暂不支持：…"），如实可纠错。
- 备选（否决）：自由条件 DSL（LLM 任意产出）——拦不住幻觉字段，违背"候选集永远来自真实数据"地基。
