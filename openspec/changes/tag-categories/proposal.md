# 提案：标签分类（tag-categories）

## Why

生产实测：24 个自定义标签平铺在 /tags 标签云一页，随打标量增长会越来越难扫——标签之间本有天然的主题 grouping（如"想读源码"/"工具"/"paper"），平铺无法表达。2026-08-23 本人拍板：给标签加分组概念，且一个标签可属多个分类（多对多）。

## What Changes

- **新表 `tag_category(tag TEXT, category TEXT, PRIMARY KEY(tag, category))`**：标签↔分类多对多映射；无映射记录的标签＝未分类。打标流程完全不写分类，新标签天然落未分类。
- **/tags 标签云页改分组展示**：每个分类一组，组内按使用次数降序（同数按标签名，沿用既有标签云口径）；底部"未分类"组放无映射标签；一标签属多分类时在多个组各出现一次（分组语义，不同于 P6"筛选不重复"）。
- **分类管理全做且全部点选式**（手机端不用拖拽，复用 T-035 自绘下拉组件形态）：
  - 新建分类；
  - 把标签加入/移出分类（一标签可属多分类）；
  - 分类改名；
  - 删除分类——其下标签映射删除、标签回落未分类；**标签本身与仓上的打标记录不动**。
- **不动的部分**：打标下拉（T-035）、榜单行标签 chips、/tags/<tag> 筛选页，全部不变——分类只是标签页的展示/管理层概念，不进任何榜单/筛选/AI 链路。

## Capabilities

### New Capabilities

- `tag-categories`: 标签分类的数据模型（多对多映射表）、/tags 分组展示口径、分类管理操作（新建/归类/改名/删除）的行为与 API 契约。

### Modified Capabilities

（无——打标、标签筛选页、榜单行 chips 均无既有 spec 覆盖且行为不变。）

## Impact

- **代码**：`app/schema.sql`（新表）、`app/web/routes.py`（`/tags` 总页分组装配＋分类管理 API 一组）、`app/web/templates/tags.html`（分组云视图＋管理控件）、`app/web/static/radar.js`（点选交互，复用自绘下拉形态）、`radar.css`（组头/控件样式）。
- **数据**：生产库建新表（schema.sql 幂等 `CREATE TABLE IF NOT EXISTS`，启动即建）；存量 24 个标签全部落未分类，无需迁移脚本。
- **测试**：新增分组装配、四类管理 API（幂等/校验/级联删除）测试；既有标签测试不受影响。
- **外部依赖**：无新增。
- **项目 SOP**：新增表＋改已验收页面（P5 /tags）→ 高风险，详情卡必填；OpenSpec change 先行；视觉为既有组件复用（自绘下拉/输入框/chip），免示意图档；A 级预演（真实库 CRUD＋级联删除＋未分类回落）＋真实页面截图交付本人走查。
