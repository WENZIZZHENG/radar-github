# 设计：智能搜索（smart-search）

## Context

家底（生产实测）：池内 3024 仓（alive，入池门槛约 1000 星）；英文描述全量、topics 非空 79%、中文译文 41%（仅 S 集）、AI 概要 33%。既有基建：`app/ai.py` DeepSeek 客户端（deepseek-chat，60s 超时，降级姿态齐备）；`app/collector/github.py` `search_repositories`（Search API，限速 30 次/分）；`ingest_followed_repo` 关注动态入池；`_row.html` 行组件与详情面板体系。

约束：单人使用、S 档；搜索是榜单的辅助功能，不得动核心链路（采集/榜单计算）；AI 任何失败不得影响榜单主链路（ai.py 既有姿态的延伸）。

## Goals / Non-Goals

**Goals:**
- 自然语言意图 → 10 条项目推荐（池内优先，池外实时补足），每条带一句推荐理由。
- 池外结果一键关注入池。

**Non-Goals:**
- 不做池子扩容（不降 1000 星入池门槛——那是核心链路地基，独立议题）。
- 不做向量/embedding 检索（S 档规模，关键词召回+LLM 精选足够）。
- 不做搜索历史/热门搜索等运营功能。
- 不引入 FTS5 索引表（3024 行 LIKE 匹配毫秒级，不值得建索引表；池子量级变化后再议）。

## Decisions

### 决策 1：三段式链路——LLM 理解、本地召回、LLM 精选
LLM 只做两件事：**把中文人话翻成结构化查询**（产出多个英文关键词 × 多个语言 × 主题词，JSON 约定格式）和**从候选里精选+写理由**；检索本身在本地 SQL 做。候选集永远来自真实池子/GitHub 真实响应，LLM 无幻觉出不存在项目的机会。
备选：FTS5 纯关键词检索——否决，理解不了"我要做爬虫"式意图；纯 LLM 推荐——否决，3024 仓喂 prompt 成本不可行且有幻觉风险。

### 决策 2：池内召回——SQL LIKE 多关键词匹配，粗排取约 30 候选
对 `repos`（dead=0）做关键词组匹配：`full_name` / `description_en` / `topics`（JSON 字符串）任一 LIKE 命中任一关键词记一次命中，语言过滤取交集；粗排键 = 命中数降序 → 最新星数降序，取约前 30 作候选。3024 行全表 LIKE 毫秒级，符合 SQL 红线（不碰 star_snapshots 大表；星数取每仓最新快照走主键索引或预聚合，实现时对齐既有口径）。
中文意图不靠中文译文匹配——LLM 直接产出英文关键词，译文覆盖率（41%）不构成瓶颈。

### 决策 3：LLM 精选——候选 30 → 10，理由一句话
把候选的 全名/描述/topics/语言/星数（/近期增量）喂给 DeepSeek，要求返回至多 10 条（按匹配度排序）+ 每条一句中文推荐理由（≤50 字，"为什么适合你的意图"视角）；LLM 返回不足 10 条按实际展示，不凑数。prompt 约束只许从候选清单中选（编号引用），防幻觉。

### 决策 4：池外补搜——池内不满 10 才触发，结果全程带"池外"标记
池内精选不足 10 条时，用决策 1 的关键词组拼 GitHub Search 查询（`keyword language:X ... sort=stars`）实时补搜，补到 10 条为止。池外结果模型与池内行同构但带 `external=True`：展示 GitHub 原始英文描述、无增星/译文/概要、带"池外"徽标。Search 失败/限速 → 池内结果照常返回，池外区标注"补搜失败"，不报错页。

### 决策 5：关注闭环复用决策 9 动态入池
池外行尾关注星复用既有关注接线：点击 → `fetch_repo` 拉单仓元数据 → `ingest_followed_repo` 入池（source='follow' + 基线快照）。已入池/已关注的池外行不显示关注星（按 full_name 查库判定）。关注后次日进入采集与翻译队列，无需任何新代码路径。

### 决策 6：降级与失败姿态（延伸 ai.py 既定姿态）
- DeepSeek key 未配置/鉴权失败/调用失败 → 搜索页展示"搜索暂不可用"明确提示（fail-loud 给用户），榜单等主链路不受影响；
- LLM 返回非法 JSON/超范围编号 → 当次精选放弃 LLM 结果，退化按粗排顺序直出池内候选（无推荐理由，页面上如实无理由），记 WARNING；
- GitHub token 缺失 → 池外补搜整段跳过（同 ai.py README 退化姿态），页面只出池内结果。

### 决策 7：页面形态——独立页，复用行组件
导航栏加"搜索"；search.html = 输入框 + 结果列表；结果行复用 `_row.html`（详情面板体系随之复用），行下加推荐理由段；池外行加徽标+关注星。无新视觉组件（输入框/按钮用现有基础样式），免示意图档，《交互流程说明》文字层确认。

## Risks / Trade-offs

- [LLM 意图理解质量不稳定（关键词给歪）] → 页面上把 LLM 解析出的关键词/语言透明显示给用户（"理解为：爬虫 / Python"），可预期可纠错；精选失败有决策 6 的粗排兜底。
- [每次搜索 1~3 次 LLM 调用有延迟（秒级）] → 结果页异步加载或加载态提示；单人使用无并发压力，不建缓存（重复搜同词代价可接受，后续痛点真出现再加）。
- [池外结果星数高但质量未经池子筛选] → "池外"徽标如实标记，排序永远池内在前、池外补足在后。
- [Search API 限速 30 次/分] → 单次搜索至多 1~2 次 Search 调用；触发限速按决策 4 降级处理。

## Migration Plan

纯增量功能：新路由/新模板/新模块，无 schema 变更、无数据迁移。部署重启即用。回滚=代码回滚重启。
